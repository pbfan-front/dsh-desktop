# 按用户指令验证

业务工作区默认只完成请求的修改或分支创建，然后交付。测试、页面探针、为验收而运行的 curl、重复构建和重启不再作为默认收尾；回复必须说明未验证。用户明确请求构建、启动或重启时仍执行该请求。

用户说“验证一下”：执行当前修改的针对性检查；“跑测试”：按所指定测试范围执行，未指定时选择相关测试；“完整验收”：才扩展到完整链路。普通“继续”和确认创建不是验证授权。

通过宿主 systemPrompt section 注入 Agent 行为策略，并调整业务工具说明。客户端自动页面检查默认关闭，创建后工作流仍停留 wait-for-preview，不能标记 verified。明确要求验证时，Agent 使用现有 resume/verify 工具及原断言；不改权限、数据格式、冲突、证据有效期等必要门禁。

边界：这是 Agent 指令策略加客户端自动检查关闭，不是对 Bash/浏览器工具实施权限拦截；模型仍可能不遵守指令。原有验证工具手动调用仍可用。不伪造工作流完成状态。

此次增加默认不自动验证的回归用例，但按用户要求未执行测试、构建、重启或页面验收。需完整重启 Desktop 加载插件与策略；只有源码修改尚不能代表运行客户端生效。未提交。
