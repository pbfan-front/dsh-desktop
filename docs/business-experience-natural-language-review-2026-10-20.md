# 2026-10-20 真实自然语言创建采样

本轮从已认可的正常/逾期借据业务预期出发，通过可见 Electron 的新会话发起需求。起始请求不提供路由、API 或 Scenario ID；不手工启动/提交/修改工作流方案。确认和分支选择由验收操作者通过面板进行，不执行还款、结清或贷款提交，不改业务源码。

## 本轮结论与覆盖限制

- 两条都是自然语言启动、Agent 生成方案，随后操作者面板确认/选择/验证的真实客户端混合闭环，最终原门禁均通过；不是无人工 Agent 自动准确率 100%。正常用例还经历具体业务预期补充及一次不必要净化倾向的纠偏。
- 现有确认前不创建、创建不启用、手动选择后的当前请求/页面门禁、返回默认和精确回滚均在真实界面通过。未执行结清、还款或贷款提交；旧 Profile、历史完成/失败结果保留。
- 对这两次本机样本，源码分析为 11–24ms，创建约 0.5 秒；方案前模型请求统计远大于这两段，但模型统计含服务和网络，不能全部归因于推理或 grep I/O。
- 原门禁只检查保存文本在页面中出现，不证明同一 DOM 卡片。此次人工可见界面确认了同卡片，但尚未形成固定评估器所需的独立原始网络+DOM文件；语料评估契约对自然语言 query 与等价来源也需单独设计，不能事后放宽来计本轮通过。
- 本轮只新增验收文档；没有实施下列优化，没有运行新的全量单元测试，也没有重启客户端、改模型/分析模式或提交代码。

## 后续优化线索（尚未实施）

1. 分离稳定业务意图与操作约束/验收补充；不能用整段约束污染精确语义规则匹配，也不能未经确认将一般自然语言强行归一为已批准意图。
2. 方案应展示具体关键字段与断言覆盖缺口，避免“正常”状态泛化命中被当作指定借据或同卡片验收。
3. 复用完整源 Scenario 时，对未要求变更的附带业务字段保持不动。发现潜在冲突时明确提出，不自行新增“数据净化”目标。
4. 聚焦读取结构化 Mock 对象/精确字段，减少大文件行号试探、截断 grep 和重复全文上下文；保留证据不足时的完整检索回退。
5. 让已声明的关键对象标识和状态形成关联断言，避免页面其它位置的相同文案代替目标卡片；在固定语料评估中保留独立请求响应与 DOM 证据，并区分直接命中、消歧后完成和人工修订后完成。
