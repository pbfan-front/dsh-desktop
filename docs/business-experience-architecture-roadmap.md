> 用途：记录 DSH Desktop 集成业务源码、CodeIntell、Mock/Profile 和侧栏体验的当前状态、待办项、验收标准与决策。

## 1. 建设目标

业务人员无需本地代码、Node.js 或 `npm install`，即可在 DSH Desktop 中：

1. 用自然语言描述业务场景。
2. 由 CodeIntell 识别页面、业务分支、接口和字段。
3. 安全地创建、应用和回滚 Mock Profile。
4. 在 Desktop 侧栏中直接体验业务页面。
5. 通过真实请求命中、DOM/文案和截图证据验证结果。
6. 业务包可独立版本化、升级、回退，不必每次重新安装 Desktop。

## 3. P0：优先闭环

### 3.1 统一业务构建流水线

**现状**

`business:sync` 会构建 Mock Platform 并同步现有 `.desktop-build/web`，但不会重新编译业务 Web。业务源码和预览产物可能不一致。

**目标**

新增统一命令，例如 `npm run business:dev:sync`，自动完成：

1. 编译 `demo-test` local-mock Web 产物。
2. 构建/更新 CodeIntell 索引。
3. 构建 Mock Platform。
4. 导出源码快照和用户工具。
5. 校验所有 Build ID 和哈希。
6. 原子替换 Desktop 业务包。

**验收标准**

- [x] 修改业务源码后仅执行一条命令即可生成最新业务包。
- [x] 业务源码、Web 产物、CodeIntell 索引任一过期时校验失败。
- [x] 失败时保留上一个可用业务包。

### 3.2 Desktop 侧栏业务页面热更新

**现状**

业务代码修改后需要“编译 → 同步 → 重启 Desktop”。

**目标**

- 开发模式允许侧栏加载本地业务 dev server（默认 `8094`）。
- 业务代码保存后 iframe 热更新或自动刷新。
- 发布模式继续加载签名的内置静态业务包。

**验收标准**

- [x] Desktop 开发版可显式切换“本地热更新/内置业务包”。
- [ ] 业务代码改动不需重启 Desktop（等待真实 GUI 热更新验收）。
- [x] 本地 dev server 不可用时有清晰错误，不静默回退到旧产物。

### 3.3 外部能力的统一 Mock Adapter

**现状**

KYC、摄像头、视频、上传等外部能力仍依赖业务代码零散的 `local-mock` 分支。

**目标**

建立统一适配层，至少包括：

- `FaceAdapter`
- `KycAdapter`
- `CameraAdapter`
- `UploadAdapter`
- `LocationAdapter`
- `NativeSdkAdapter`

正式环境使用真实实现，Desktop 体验环境使用可配置 Mock 实现。

**验收标准**

- [x] 外部域名、摄像头和 Native SDK 不再阻塞 Desktop 体验。
- [x] 新外部能力无需在多个 Interactor 里重复判断 `local-mock`。
- [x] 正式环境行为与改造前一致。

### 3.4 缺失 API Mock 的受控补全

**现状**

创建场景主要依赖已有 `mock.json`。缺少 Mock 定义时可能出现“未命中白名单”、空场景或业务页系统繁忙。

**目标**

- 根据 Req/Rsp TypeScript 类型生成基础 Mock。
- 自动识别项目响应外层。
- 仅允许 CodeIntell 证据确认的 API 创建 Mock。
- 写入后立即执行真实请求命中验证。

**验收标准**

- [x] 有类型定义但无 `mock.json` 的 API 可安全创建首个场景。
- [x] 拒绝未经证据确认的 API 或字段。
- [x] 不会生成重复 `data.data` 响应结构。

### 3.5 真实页面端到端验收

**目标场景**

- 额度页
- 借据列表
- 企业/个人切换
- 借款申请
- 收款账户
- KYC 刷脸/视频录制
- 还款查询

**验收链路**

```text
应用 Profile
→ 打开指定路由
→ 点击真实按钮
→ 检查 Mock 请求命中
→ 检查 DOM/可见文案
→ 必要时截图比对
→ 回滚测试数据
```

**验收标准**

- [ ] 每个核心业务域至少有一个成功场景和一个失败场景。
- [ ] 自动验收失败能区分路由、接口、字段和 UI 断言问题。

### 4.5 有状态业务工作流

**目标**

将“场景分析 → Mock 方案 → 用户确认 → 应用 → 请求命中 → 页面验证 → 保存”从自由 Agent 对话收敛为可观察、可恢复的工作流。Desktop 宿主负责执行、状态和门禁，业务插件负责工作流定义及业务处理器，Agent 只处理需要推理的步骤。

**当前进度**

- [x] `WF-001`：定义 Workflow、Run、Step、Evidence、错误和状态契约。
- [x] `WF-002`：实现与 Electron 解耦的串行执行器、注册机制、Agent/确定性步骤、Checkpoint、重试和取消。
- [x] `WF-003`：将运行状态原子持久化，并在 Desktop 重启后恢复。
- [x] `WF-004`：增加宿主 IPC、暂停/继续/取消/重试入口和运行时间线查询。
- [x] `WF-005`：把现有业务场景创建流程接入工作流。
  - [x] 宿主固定流程已接通：分析 → 方案确认 → 创建 → 应用 → 页面就绪确认 → 验证。
  - [x] 复用现有业务服务的证据、写入、应用和严格验证接口；失败可重试且不会绕过原有门禁。
  - [x] Agent 插件提供工作流启动、继续、状态、重试和取消工具，通过受控子进程消息桥调用宿主运行时；旧工具保留为回退路径。
  - [x] 完成真实 Desktop GUI 验收；旧入口已收敛为显式启用的兼容回退路径。
- [x] `WF-006`：增加工作流运行记录与可观测性界面，真实 Desktop GUI 验收通过。
- [x] `WF-007`：业务插件导出带 Schema 的工作流定义和处理器声明；宿主仅接受白名单处理器和固定安全拓扑。
- [x] `WF-008`：把当前 Profile、同 revision 页面观测、路由、文本断言和真实 Scenario 请求命中变成不可绕过的通用确定性门禁。
- [x] `WF-009`：增加工作流版本、插件身份和步骤拓扑兼容门禁；旧完成记录可读，旧活动流程仅在显式兼容时迁移。
- [x] `WF-010`：默认使用有状态工作流；旧分析/创建/应用/验证工具默认禁用，仅可显式切换到 `legacy` 回退，并记录模式与调用审计。

当前执行器已注册到 Desktop 启动入口，运行记录随业务数据持久化，并通过受信任主窗口的窄 IPC 提供列表、详情、继续、重试和取消能力。业务插件可声明工作流 Schema、步骤和白名单处理器名称，但不能注册任意代码；场景工作流仍由宿主校验固定拓扑后执行。

### 4.6 体验目标解析

- [x] 当前页面仅作为常见情况下的兜底上下文，不再强制等同于目标页面。
- [x] 按“显式路由 → 业务页面名称 → 对话意图 → 当前预览”顺序确定分析目标。
- [x] 业务插件可声明页面别名，解决源码路由标题与用户业务叫法不一致的问题。
- [x] 多个候选相同置信度时返回明确歧义错误，不静默猜选页面。
- [x] 目标解析完成后仍由 CodeIntell 对最终路由重新执行源码证据分析。

### 4.7 有界证据包与现有场景复用

- [x] 分析结果在保留完整证据候选的同时，单独输出最多六个重点 API。
- [x] 根据业务意图保守匹配已有 Scenario，优先复用已验证的 Mock 数据。
- [x] 显式 API、已有场景匹配和普通证据排序使用不同策略与置信度。
- [x] 只有重点候选不足以表达目标状态时才建议继续搜索源码，避免全仓重复 grep。
- [x] 所有建议仍需经过工作流确认点、写入证据和真实预览验证门禁。

### 4.8 场景方案安全草案

- [x] 唯一且置信度足够的已有 Scenario 匹配可生成结构化方案草案。
- [x] 草案使用 `sourceScenarioId` 复用现有数据，不把大块响应复制进 Agent 上下文。
- [x] 业务运行时在写入时重新读取并校验源 Scenario，防止陈旧或伪造引用。
- [x] 草案固定停留在 `confirm-plan`，确认前不创建 Profile、不修改 Mock。
- [x] 低置信、并列候选和新业务状态不生成草案，继续使用人工方案流程。

## 5. P2：发布与规模化

### 5.1 正式发布链路

- [ ] macOS 正式签名和公证。
- [ ] Windows 原生构建和签名。
- [ ] macOS/Windows 干净机器安装验收。
- [ ] 覆盖安装、卸载重装和连续版本升级验收。
- [ ] 升级失败自动回退上一个已验证版本。

### 5.2 业务包独立增量更新

建议拆分四个版本：

1. Desktop 壳版本。
2. 业务 Web 包版本。
3. 源码/CodeIntell 包版本。
4. 内置 Mock 包版本。

- [ ] 业务包有独立签名、版本和兼容性声明。（版本、兼容性和逐文件 SHA-256 已完成，待正式签名）
- [ ] Desktop 壳未变更时只下载业务包。
- [x] 更新失败保留并恢复上一个业务包。
- [x] 更新过程不删除用户场景数据。

### 5.3 多业务项目

- [ ] 一个 Desktop 可管理多个业务工程。
- [ ] 每个项目独立管理源码、索引、Mock、Profile 和用户数据。
- [ ] 支持项目版本切换和兼容性校验。
- [ ] 不同项目的对话和预览状态不串用。

## 6. 建议实施顺序

1. 统一“业务 Web 编译 + CodeIntell 建索引 + `business:sync`”。
2. 支持 Desktop 侧栏加载业务 dev server 和热更新。
3. 抽象 KYC、摄像头、视频和上传等外部能力的 Mock Adapter。
4. 支持缺失 `mock.json` 时受控创建基础 Mock。
5. 扩充真实页面端到端验收集。
6. 完善用户数据迁移和 CodeIntell 生命周期。
7. 完成业务包独立更新、签名和跨平台发布。
