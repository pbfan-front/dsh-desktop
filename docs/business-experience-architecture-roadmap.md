> 用途：记录 DSH Desktop 集成业务源码、CodeIntell、Mock/Profile 和侧栏体验的当前状态、待办项、验收标准与决策。

## 1. 建设目标

业务人员无需本地代码、Node.js 或 `npm install`，即可在 DSH Desktop 中：

1. 用自然语言描述业务场景。
2. 由 CodeIntell 识别页面、业务分支、接口和字段。
3. 安全地创建、应用和回滚 Mock Profile。
4. 在 Desktop 侧栏中直接体验业务页面。
5. 通过真实请求命中、DOM/文案和截图证据验证结果。
6. 业务包可独立版本化、升级、回退，不必每次重新安装 Desktop。

## 3. P0：优先闭环

### 3.1 统一业务构建流水线

**现状**

`business:sync` 会构建 Mock Platform 并同步现有 `.desktop-build/web`，但不会重新编译业务 Web。业务源码和预览产物可能不一致。

**目标**

新增统一命令，例如 `npm run business:dev:sync`，自动完成：

1. 编译 `demo-test` local-mock Web 产物。
2. 构建/更新 CodeIntell 索引。
3. 构建 Mock Platform。
4. 导出源码快照和用户工具。
5. 校验所有 Build ID 和哈希。
6. 原子替换 Desktop 业务包。

**验收标准**

- [x] 修改业务源码后仅执行一条命令即可生成最新业务包。
- [x] 业务源码、Web 产物、CodeIntell 索引任一过期时校验失败。
- [x] 失败时保留上一个可用业务包。

### 3.2 Desktop 侧栏业务页面热更新

**现状**

业务代码修改后需要“编译 → 同步 → 重启 Desktop”。

**目标**

- 开发模式允许侧栏加载本地业务 dev server（默认 `8094`）。
- 业务代码保存后 iframe 热更新或自动刷新。
- 发布模式继续加载签名的内置静态业务包。

**验收标准**

- [x] Desktop 开发版可显式切换“本地热更新/内置业务包”。
- [ ] 业务代码改动不需重启 Desktop（等待真实 GUI 热更新验收）。
- [x] 本地 dev server 不可用时有清晰错误，不静默回退到旧产物。

### 3.3 外部能力的统一 Mock Adapter

**现状**

KYC、摄像头、视频、上传等外部能力仍依赖业务代码零散的 `local-mock` 分支。

**目标**

建立统一适配层，至少包括：

- `FaceAdapter`
- `KycAdapter`
- `CameraAdapter`
- `UploadAdapter`
- `LocationAdapter`
- `NativeSdkAdapter`

正式环境使用真实实现，Desktop 体验环境使用可配置 Mock 实现。

**验收标准**

- [ ] 外部域名、摄像头和 Native SDK 不再阻塞 Desktop 体验。
- [ ] 新外部能力无需在多个 Interactor 里重复判断 `local-mock`。
- [ ] 正式环境行为与改造前一致。

### 3.4 缺失 API Mock 的受控补全

**现状**

创建场景主要依赖已有 `mock.json`。缺少 Mock 定义时可能出现“未命中白名单”、空场景或业务页系统繁忙。

**目标**

- 根据 Req/Rsp TypeScript 类型生成基础 Mock。
- 自动识别项目响应外层。
- 仅允许 CodeIntell 证据确认的 API 创建 Mock。
- 写入后立即执行真实请求命中验证。

**验收标准**

- [ ] 有类型定义但无 `mock.json` 的 API 可安全创建首个场景。
- [ ] 拒绝未经证据确认的 API 或字段。
- [ ] 不会生成重复 `data.data` 响应结构。

### 3.5 真实页面端到端验收

**目标场景**

- 额度页
- 借据列表
- 企业/个人切换
- 借款申请
- 收款账户
- KYC 刷脸/视频录制
- 还款查询

**验收链路**

```text
应用 Profile
→ 打开指定路由
→ 点击真实按钮
→ 检查 Mock 请求命中
→ 检查 DOM/可见文案
→ 必要时截图比对
→ 回滚测试数据
```

**验收标准**

- [ ] 每个核心业务域至少有一个成功场景和一个失败场景。
- [ ] 自动验收失败能区分路由、接口、字段和 UI 断言问题。

## 4. P1：产品化闭环

### 4.1 用户 Mock 数据版本与迁移

- [ ] Profile/Scenario Schema 有显式版本。
- [ ] 内置 API Mock 升级后检测用户场景冲突。
- [ ] 接口字段变更时可自动迁移或标记待修复。
- [ ] 支持用户场景导入、导出和跨机器迁移。
- [ ] 客户端覆盖安装、卸载和重装时有明确的数据保留策略。

### 4.2 CodeIntell 生命周期

- [ ] 源码变更时自动执行增量建索引。
- [ ] 索引 Build ID 与源码和业务 Web Build ID 强绑定。
- [ ] Desktop 启动时检查过期、损坏和版本不兼容。
- [ ] 索引异常可自动重建或降级。
- [ ] UI 展示索引版本、新鲜度、覆盖率和最近错误。

### 4.3 业务运行时自恢复

- [ ] 业务服务退出后自动拉起，无需重启 Desktop。
- [ ] UI 提供“重启业务预览”和日志入口。
- [ ] 重启后恢复当前对话、Profile、路由和预览状态。
- [ ] 健康检查区分“服务未启动”、“业务包不兼容”和“页面加载失败”。

### 4.4 场景结果可解释性

- [ ] 显示本次场景涉及的 API、Scenario 和字段差异。
- [ ] 显示“为什么这些字段可触发目标页面”的证据链。
- [ ] 显示真实命中请求、页面路由和 UI 断言结果。
- [ ] “创建成功”与“业务验证成功”使用不同状态。

## 5. P2：发布与规模化

### 5.1 正式发布链路

- [ ] macOS 正式签名和公证。
- [ ] Windows 原生构建和签名。
- [ ] macOS/Windows 干净机器安装验收。
- [ ] 覆盖安装、卸载重装和连续版本升级验收。
- [ ] 升级失败自动回退上一个已验证版本。

### 5.2 业务包独立增量更新

建议拆分四个版本：

1. Desktop 壳版本。
2. 业务 Web 包版本。
3. 源码/CodeIntell 包版本。
4. 内置 Mock 包版本。

- [ ] 业务包有独立签名、版本和兼容性声明。
- [ ] Desktop 壳未变更时只下载业务包。
- [ ] 更新失败保留并恢复上一个业务包。
- [ ] 更新过程不删除用户场景数据。

### 5.3 多业务项目

- [ ] 一个 Desktop 可管理多个业务工程。
- [ ] 每个项目独立管理源码、索引、Mock、Profile 和用户数据。
- [ ] 支持项目版本切换和兼容性校验。
- [ ] 不同项目的对话和预览状态不串用。

## 6. 建议实施顺序

1. 统一“业务 Web 编译 + CodeIntell 建索引 + `business:sync`”。
2. 支持 Desktop 侧栏加载业务 dev server 和热更新。
3. 抽象 KYC、摄像头、视频和上传等外部能力的 Mock Adapter。
4. 支持缺失 `mock.json` 时受控创建基础 Mock。
5. 扩充真实页面端到端验收集。
6. 完善用户数据迁移和 CodeIntell 生命周期。
7. 完成业务包独立更新、签名和跨平台发布。
