# 日常体验流程：对话确认、手动选分支、后台核验

日期：2026-10-22。BEA-059；迁移台账 DSH-BIZ-094。尚未提交。

## 日常操作

1. 在对话中描述需求，助手分析并提交完整方案。
2. 输入框上方出现确认卡，简要展示分支、页面和状态；方案、来源及完整正负断言可展开查看。点击“确认并创建分支”即可，不要求先打开工作流面板或再勾一次复选框。
3. 创建只新增分支，保留当前选择；用户在业务体验中手动勾选新分支。
4. 对于新运行中明确声明的页面检查，当前可见会话在收到匹配分支/页面的观察后自动核验。跨页时仅提示用户正常打开下一页，不反复要求点击验证，不导航或提交业务操作。
5. 检查全部通过后，对话输入框上方不再显示结果卡（标题、通过状态、打开业务体验/高级诊断按钮一并收起）；完整结果保留在高级诊断。

原工作流面板改名为“高级诊断”，不因提案或目标歧义自动弹出。完整历史、证据、手动确认/核验及技术错误仍可按需查看。常用流程不依赖打开此面板。

这是现有工作流的交互调整，不是新建 Agent Runtime，也没有继续此前暂停的检索/缓存优化。

## 实现与权限边界

- `dsh-desktop-business-ui/client.js` 使用 Harness 已发布的 `conversation.input.dock` 列表扩展位；不改写聊天 DOM、不替换其他贡献项。公共 owner 为 InputZone，沿用会话 scope。确认卡与原任务/队列可以同时存在。
- 独立模块 `client.experience-flow.js` 按当前 Harness 的 package-local `client.*.js` chunk 协议加载。同包 require.async、相同模块 ID/chunk 名，失败只影响卡片并给出高级入口，不阻止宿主启动。
- 卡片点击继续原 `approveBusinessWorkflowProposal(runId,{proposalId,sessionId})`，不把方案重新传给 Main。原可信窗口/主 frame、会话、版本、来源实时复核、质量及持久化门禁不变。模型没有新增批准入口。
- 新运行由 Main 写入 `experienceFlowVersion=1`，不是模型可传的审批标记；旧运行不回填、不自动推进。缺少 verificationSteps 的旧单页方式保留，不猜测验收断言。
- 工具说明要求新方案明确给出 1–5 个页面检查，即使仅一个页面也显式声明；不能为了自动化编造或删减断言。提案仍不等于创建或页面通过。
- Runtime 在记录既有 `page-observation-ui` 后，仅通过子进程消息发布会话、Profile、revision/revisionId、路由、时间及内容指纹，不发布页面正文或 token。Main 对 metadata 做边界校验且忽略过期子进程消息；preload 只暴露可取消的只读订阅，没有新通用 IPC 或审批 HTTP 端点。
- 当前会话的可见确认卡收到匹配观察后，防抖 700ms，只发送既有下一步 `{stepId}`。原检查点重新读取真实 Profile/API 命中和页面证据，校验同激活版本、顺序、断言；末步仍执行完整 API 与当前末页的最终门禁。观察指纹仅用于调度，绝不是“验证通过”的证据。

## 失败与生命周期

未选分支、页面不符属于正常等待，只给简短下一步提示，不调用验证接口、不弹长篇红色错误。匹配页面仍加载或条件不满足时显示“待核验”，技术信息折叠；同一 run/step/指纹失败不会循环重试。页面证据变化后允许一次新尝试，也有明确的“重新检查”兜底。

已有页面通过后再次选择分支/重启 Runtime，不混用旧激活身份。用户明确点击“重新核验”才走原 restartVerification，保留上一轮采集供诊断，不自动删除证据。最终门禁失败保留失败状态，不能包装成成功。

同一时刻仅一个操作；确认按钮绑定渲染时的提案版本，连续点击、旧版本拒绝。切换会话/卸载取消待发定时器并解除订阅；隐藏窗口取消待发定时器，保留订阅以便恢复可见后继续。晚到的列表、旧运行或旧观察不能覆盖新状态。已发出的原 IPC 不能伪装为可中止事务，后续反馈不会投到新会话，原服务端仍执行会话与身份校验。

后台检查仅在当前会话卡片挂载且窗口可见时响应实际观察，不是持续后台巡检；未进入的跨页步骤、从未收到新观察的页面、没有声明的条件均保持未验证。只有接口变化而页面未产生新观察时可用“重新检查”或继续正常操作触发新观察，不增加无界轮询。

## 展示与兼容

采用渐进展示：一个主创建按钮、简短结果，完整方案与技术诊断折叠。复用现有 Harness 语义 token、字号、原生 details/select 和中英文 locale；不引入字体、主题或组件库。键盘焦点、按钮忙碌/禁用、aria-live、窄宽度换行及 reduced-motion 均在组件中处理。

高级诊断的旧确认/逐页验证按钮和原对话工具路径继续有效。重建/迁移时同时同步 Main、preload、Runtime、工具插件、UI 入口和新增 chunk；UI 入口与 chunk 必须成组分发，不能单独替换 immutable 资源。默认 npm 包文件清单及既有 node_modules 分发包含它们，不修改第三方包或额外放宽 CSP。

不需要改业务源码、Mock、CodeIntell、工作流六步声明或重新导出业务包，不清空 Profile。回退本条时成组恢复展示/消息/标记/工具说明；保留持久化历史及原安全门禁，已有标记作为普通附加 context 不影响旧手动路径。
