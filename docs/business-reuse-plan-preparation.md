# 聚焦字段批读与完整来源复用方案准备（BEA-057）

[上一轮真实对话](business-source-evidence-natural-language-review-2026-10-21.md)中，源码检索已经减少，但已知业务字段和响应状态分三次读取，提案前的两个模型阶段合计约 124 秒。本条减少机械组装与重复叙述的必要性，不把单次模型等待归因为 JSON 序列化，也不预先声称创建提速。

## 边界与实现位置

仅修改宿主维护的 `packages/dsh-desktop-business`：新增纯转换模块 `reuse-plan.js`，由既有插件入口使用。没有新增工具、HTTP/IPC 端点、依赖、模型配置、UI 或业务 Runtime/Main 创建路径。

`business_propose_scenario_plan` 仍接受相同的 `runId`、`planJson`。默认完整方案保持原样；显式选择 `format=source-reuse-v1` 时，在发送原 `/__desktop/workflow/propose-plan` 前展开成完整 `profileId/label/page/scenarios/verificationSteps`。Main 收到的仍是原协议，随后执行原会话、检查点、来源/语义、版本保存和确认/创建门禁。

这不是“接受分析器推荐方案”或“自动批准复用”：API、来源 Scenario、各页正负断言都必须由 Agent 聚焦复核后明确传入。它不读 suggestedPlan、不推断意图、不选择 API/来源、不读取或重写 Mock、不把投影拼成完整数据；确认和创建时仍按既有规则校验当前有效来源。证据不足、过期或业务字段变化，不会因简写而获得创建权限。

## 可选输入格式

```json
{
  "format": "source-reuse-v1",
  "profileId": "loan_review",
  "label": "已复核的业务场景",
  "page": "loan",
  "reuse": [
    { "apiUrl": "/loan/detail.json", "sourceScenarioId": "已复核的完整来源" }
  ],
  "checks": [
    {
      "route": "/loan/detail",
      "containsText": ["借据00001", "逾期"],
      "absentText": ["系统繁忙"]
    }
  ]
}
```

- 根字段仅接受 format/profileId/label/page/reuse/checks；reuse 为 1–12 个 API 唯一的显式来源，条目只接受 apiUrl/sourceScenarioId/可选 label。生成稳定 `reuse_<32位十六进制>` ID，哈希输入为未经归一化的 `[profileId,apiUrl,sourceScenarioId]`，与来源排序无关。默认场景标签为精确来源 ID。
- checks 为 1–5 个有序页面，条目只接受 route/containsText/absentText/可选 label/apiUrls。生成 `check_1` 等机械 ID，标签默认是原路由；路由超过 200 字符时必须给不超过 200 字符的明确标签，不截断路由。第一步是否匹配原分析目标继续由 Main 验证。
- 正负断言都须显式给出，containsText 至少一项；每类最多 20 个、不超过 200 字符的非空字符串，absentText 可为 []。原文、顺序和重复值均保留，不净化、缩短或推导断言。
- 可选 apiUrls 必须非空、最多 12 个，并且全部属于传入的复用 API；不猜测缺失过滤条件。
- Profile ID、标签、page、路径和来源 ID 沿用原计划边界；简写输入最多 131072 个 JS 字符。新增或修改 Mock 数据、自定义 Scenario/检查 ID、混合复用/新数据、或本格式不支持的属性，继续使用原完整方案。
- 简写中的 data/scenarios/verificationSteps/confirmed、拼写错误和任何未知属性都会明确失败，不静默丢弃。未知 format 也拒绝。没有 format 的完整方案不经过这套转换，原 Main/Runtime 校验继续负责其有效性。

输入解析只做机械展开和局部格式检查；没有签发新的分析证据，也没有省略真实请求/页面验证。每次成功提交仍产生新的随机提案版本，旧勾选失效；生成的 Scenario ID 稳定不代表提案已确认。

## 字段批读与回复提示

既有工具说明现在明确：如果业务字段类型路径及所需响应状态路径已经有证据，第一次 `business_inspect_mock_scenario` 就一起传入必要路径，仍最多 16 条。未知结构才先请求根结构，超过预算仍按原分批恢复规则，不自动填充预设 status/http/msg、不合并多个文件快照、不扩大输出上限或按成功信封判定整个页面成功。

这一部分是 Agent 使用提示，不是后台自动批处理，不保证新自然语言样本会遵循。来源选择、特殊字段调查和必要 grep/read 回退继续保留，不为减少调用次数省略复核。用户更新应简短，区分源码支持、接口成功与最终页面已验；这也只是工具提示，不是模型输出的强制过滤器。
